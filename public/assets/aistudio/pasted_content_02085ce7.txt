1. Understand the project
Your Hospital Management System will be a web application where administrators, doctors, receptionists, and patients can manage hospital operations.

Main features
Admin dashboard

Manage users, doctors, departments, appointments, and hospital statistics.

Doctor module

View appointments, access authorized patient records, and add consultation notes or prescriptions.

Patient module

Register, log in, view doctors, book appointments, and check appointment status.

Receptionist module

Register patients, schedule visits, and manage appointment queues.

For your first version, build authentication, patient management, doctor management, appointments, and dashboards. Add billing, pharmacy, laboratory reports, and inventory after the core application works.

Step 5.2 — Configure MongoDB
In backend/.env, add your connection settings:


env
PORT=5000
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_long_random_secret
CLIENT_URL=http://localhost:5173
Replace the MongoDB value with your actual connection string. Never commit .env to Git or expose your database password.

Create config/db.js:


javascript
const mongoose = require("mongoose");

async function connectDB() {
  await mongoose.connect(process.env.MONGO_URI);
  console.log("MongoDB connected");
}

module.exports = connectDB;
Step 5.3 — Create the Express server
In server.js:


javascript
require("dotenv").config();

const express = require("express");
const cors = require("cors");
const connectDB = require("./config/db");

const app = express();

app.use(cors({
  origin: process.env.CLIENT_URL,
}));

app.use(express.json());

app.get("/api/health", (req, res) => {
  res.json({ message: "Hospital API is running" });
});

const PORT = process.env.PORT || 5000;

connectDB()
  .then(() => {
    app.listen(PORT, () => {
      console.log(`Server running on port ${PORT}`);
    });
  })
  .catch((error) => {
    console.error("Database connection failed:", error.message);
    process.exit(1);
  });
Add a development script in backend/package.json:

"scripts": {
  "start": "node server.js",
  "dev": "nodemon server.js"
}
Start the server:

6. Design the MongoDB models
Start with four main collections.

Suggested initial schemas — add fields and indexes as your application grows.

User model
Stores authentication and role information.


javascript
{
  name: String,
  email: String,
  password: String, // store a bcrypt hash
  role: {
    type: String,
    enum: ["admin", "doctor", "receptionist", "patient"]
  },
  isActive: Boolean
}
Doctor model

javascript
{
  user: ObjectId,
  specialization: String,
  department: String,
  consultationFee: Number,
  availableSlots: [String]
}
Patient model

javascript
{
  user: ObjectId,
  dateOfBirth: Date,
  contactNumber: String,
  address: String,
  emergencyContact: String
}
Appointment model

javascript
{
  patient: ObjectId,
  doctor: ObjectId,
  appointmentDate: Date,
  reason: String,
  status: {
    type: String,
    enum: [
      "pending",
      "confirmed",
      "completed",
      "cancelled"
    ],
    default: "pending"
  }
}
Use Mongoose references between related collections. Add server-side validation and indexes to prevent duplicate appointments for the same doctor and time slot.

7. Implement authentication and authorization
Create the following API endpoints:

Method

Endpoint

Purpose

POST

/api/auth/register

Register a patient

POST

/api/auth/login

Log in

GET

/api/auth/me

Get the authenticated user

POST

/api/auth/logout

Log out or clear the session

Your authentication workflow should be:

Validate registration and login input.

Hash passwords using bcryptjs.

Compare password hashes during login.

Issue a JWT after successful authentication.

Verify the token in protected routes.

Check the user's role before allowing administrative or clinical actions.

Important: Do not let public registration create admin or doctor accounts. Restrict staff creation to authorized administrators. For production, use secure cookie-based sessions or carefully configure token storage, expiration, and revocation.

Apply role-based permissions to every protected endpoint. For example, a patient must not be able to read another patient's records by changing an ID in a URL.

Duplicate booking prevention.

Consistent API error responses.

Input validation and rate limiting.

10. Connect the frontend and backend
Example: fetch the doctor list from React.


jsx
import { useEffect, useState } from "react";
import api from "../services/api";

export default function Doctors() {
  const [doctors, setDoctors] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    api.get("/doctors")
      .then((response) => setDoctors(response.data))
      .catch(() => setError("Unable to load doctors"))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading doctors...</p>;
  if (error) return <p>{error}</p>;

  return (
    <div>
      <h1>Doctors</h1>
      {doctors.map((doctor) => (
        <div key={doctor._id}>
          {doctor.name} — {doctor.specialization}
        </div>
      ))}
    </div>
  );
}
Adapt doctor.name to your actual API response shape, especially if the doctor's name is populated from a referenced User document.

11. Test the application
Before deployment, test each role independently.


Patient can register and log in.

Admin can create and manage doctors.

Receptionist can register patients and schedule appointments.

Doctor can view authorized appointments and update consultation records.

Patients can only access their own information.

Appointment conflicts are rejected on the server.

Invalid data produces useful validation errors.

Unauthorized users cannot access restricted APIs.

The application works on mobile and desktop.
Use Postman or another API client to test backend endpoints before connecting each frontend page.

Since this project handles sensitive healthcare information, use synthetic patient data while developing. A real deployment requires stronger access controls, audit logging, backups, secure deployment, and compliance with the healthcare privacy rules applicable in your country.

12. Deploy your project
A typical deployment setup is:

Frontend: Vercel or Netlify.

Backend: Render or another Node.js hosting provider.

Database: MongoDB Atlas.

Configure environment variables on the hosting providers, set the correct CORS origin, use HTTPS, and never commit credentials to GitHub.
